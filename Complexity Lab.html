Complexity Lab

An algorithm that is fast on typical input can be very slow on carefully chosen input. If an attacker controls the input, a small request can make a server do a huge amount of work. Here you will count the work and see where the blow-up comes from. Everything is a simulation: it counts operations rather than measuring real systems.

A hash table is fast only if keys spread across buckets. This toy table uses chaining: each insert walks the chain in its bucket to check for duplicates. If every key lands in one bucket, n inserts cost about n²/2 comparisons. The "public" hash below is a deliberately simple toy (sum of character codes), so keys that all share a bucket are easy to describe.

Quicksort averages about n·log₂n comparisons, but its worst case is about n²/2. Whether you hit the worst case depends on the input order and how the pivot is chosen. An attacker who knows the pivot rule can pick an input that triggers it.
